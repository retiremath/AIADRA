Acceptance criterion (`every line runs cleanly with no manual fixup; resulting sidecars/events/manifest fold-consistency check passes`) met.
- **Materialized `satisfies` inside Part Revision per [ADR/0009 §5](../../Docs/ADR/0009-relationship-type-satisfies.md)** — `outputs/revisions/0193abcd-1234-7890-abcd-111111111111/0193abcd-1234-7890-abcd-333333333333.yaml` shows `binding: fixed` + `endpoints[0].revision_id` pinned to the released Requirement Revision. The Manifest pins the Part Revision's content hash; the materialized `satisfies` is transitively pinned because the Revision file is immutable. **No separate relationship-Revision artifact** (the [Codex1 B1 catch in arc 20260520-2](../../Discussions/20260520/20260520-2/Codex1.md) holds in practice).
- **AIADRA YAML Profile spike-grade lint rejects all 6 negative fixtures** — `test_profile_negative.py` covers anchors, aliases, merge keys, custom tags, duplicate keys, YAML 1.1 directive. All rejected at read time, not silently accepted. Per [Codex1 N1 (arc 20260530-1)](Codex1.md) acceptance criterion.
- **Manifest content-hashable + deterministic** — `json.dumps(..., sort_keys=True, separators=(",", ":"))` produces byte-stable output; SHA-256 over the canonical bytes gives a reproducible release hash. Manifest does NOT pin acceleration-cache state per [ADR/0001 §3](../../Docs/ADR/0001-storage-substrate.md).
- **Rejected transaction produces no canonical artifact** per [OQ-0003](../../Docs/OpenQuestions.md) — `propose-parameter-change --new-value 4` (below threshold) exits 1, prints rejection to stdout, leaves the workspace byte-identical. No checked-in audit-log artifact created. Verified via filesystem diff after the rejected run.
- **Number allocation atomicity** per [ADR/0004 §6](../../Docs/ADR/0004-number-allocation.md) — `Reservations/P.yaml` and `Reservations/REQ.yaml` entries match sidecar `object.uuid` and event `payload.uuid` for every created Object. Cross-artifact identity cross-check holds.

## 2. Friction encountered

- **[LOAD-BEARING — [ADR/0001 §4](../../Docs/ADR/0001-storage-substrate.md) + [ADR/0019 §4](../../Docs/ADR/0019-object-type-evidence-artifact.md)] `parameter_changed` event payload cannot derive `fact_provenance` mutation.** Initial spike updated `parameter.fact_provenance.category` from `human_input` to `ai_proposal` in `transaction.change_parameter` (the AI Action Protocol surface) — fold check then failed because the `parameter_changed` event carries only `{old_value, new_value, rationale}`. Spike-grade workaround: don't mutate `fact_provenance` (sidecar parameter stays `human_input` even after AI-proposed change). Detected by the fold check itself, which is exactly the design intent of [ADR/0001 §4](../../Docs/ADR/0001-storage-substrate.md) — the invariant catches latent drift. **Production must address.** Two clean fixes: (a) extend the `parameter_changed` event payload with `new_fact_provenance`; (b) define a fold rule that `parameter_changed` → `category: ai_proposal` (AI-Action-Protocol-driven by definition).
- **[LOAD-BEARING — [ADR/0006 §8](../../Docs/ADR/0006-object-type-requirement.md)] Acceptance criterion threshold-expression has no canonical primitive.** Per [Codex1 B2 (arc 20260530-1)](Codex1.md), Requirement schema carries `criterion: {text, language, format}` + optional `references[]` — no structured threshold. Wedge needs a deterministic check for `plate_thickness_mm >= 5`. Spike-local convention: CLI parses `--acceptance-criterion ac_id:param>=value` and synthesizes criterion text `"<param> shall be at least <value>"`; spike validator regex-parses that exact text shape to extract `(param, threshold)`. **Production needs one of:** (i) Schema Change Note adding canonical threshold-expression primitives to `acceptance_criterion`; (ii) richer criterion DSL with formal grammar; (iii) tooling-aided diagnostic only with no structural enforcement (matches verification-method consistency posture per [ADR/0021 §"Decision §7"](../../Docs/ADR/0021-relationship-types-v-and-v.md)). Friction surfaces the gap that V&V framework left open — `verifies` exists, but the threshold-check itself is implementation-defined.
- **[LOAD-BEARING — [ADR/0004 §6](../../Docs/ADR/0004-number-allocation.md)] Cross-artifact atomicity gap survives at spike grade.** Per Claude1 Design Decision D, the spike does per-artifact temp-file-then-rename (`os.replace`) but provides NO cross-file atomicity. A crash between sidecar write and event append leaves the sidecar/event invariant violated. Per Codex1 N3 (arc 20260530-1), this is acceptable at spike grade. **Production must adopt one of:** write-ahead log; git-commit-as-atomic-boundary (the [ADR/0004 §6](../../Docs/ADR/0004-number-allocation.md) intent — "Same Git commit MUST contain..."); or a transaction-manager wrapping the three writes. Not addressable by the spike's filesystem-only model.
- **[MODERATE] Workspace path divergence from [ADR/0023 §"Worked invocation"](../../Docs/ADR/0023-wedge-spike-scope-and-runtime.md).** ADR/0023's worked invocation shows `Docs/Reservations/P.yaml` paths (AIADRA repo layout), but the spike workspace is a standalone directory where `Docs/` makes no sense. Spike used `Reservations/P.yaml` directly under `--workspace`. Production needs to clarify: are Reservation paths repo-relative-with-`Docs/`-prefix, workspace-relative, or both (different conventions for Wedge vs production)?
- **[MODERATE] `schema_version` placement inconsistent across ADRs.** ADR/0002 worked example: top-level `schema_version`. ADR/0004 §3 example: frontmatter `schema_version`. ADR/0006 / ADR/0009 worked examples: `object.schema_version` (inside the `object` block). Spike adopted: `object.schema_version` for sidecars/Revisions, top-level for events/manifest, frontmatter-fields-flattened-to-top-level for Reservations. A future ADR clarifying placement-per-artifact-kind would prevent each new artifact-kind ADR from re-deciding.
- **[MODERATE] Event payload `initial_sidecar` is heavier than likely production-grade.** Spike's `part_created` / `requirement_created` events carry the full initial sidecar in `payload.initial_sidecar` so the fold can reconstruct state without separate sidecar reads. Production probably wants delta-only events; fold derives current state from the event stream alone (the [ADR/0010 / ADR/0011 / ADR/0017](../../Docs/ADR/0010-relationship-type-composed-of.md) worked sidecars suggest sidecars are also a checkpoint of derivable state, not the authoritative event payload). At Tier-S scale the size cost is negligible; at Tier-L it adds up. **Per [Codex1 §"Responses to requested feedback" item 3 (arc 20260530-1)](Codex1.md):** "`initial_sidecar` is heavy but acceptable as spike-local."
- **[MINOR] `merge_key.yaml` negative fixture rejected as "aliases" not "merge keys".** `<<: *defaults` triggers the alias check before the merge-key check because the regex scan is order-dependent. Rejection is correct (both forbidden), but the error message is misleading. Production lint should detect merge keys distinctly for clearer diagnostics.
- **[MINOR] Windows console (cp1252) cannot render `✓` / `✗` marks** from [ADR/0023 §"Worked invocation"](../../Docs/ADR/0023-wedge-spike-scope-and-runtime.md). Spike-grade workaround: `sys.stdout.reconfigure(encoding="utf-8")` at CLI entry. Production should standardize on UTF-8 stdout/stderr across platforms (env var, CI config, or per-platform launcher).
- **[MINOR] Spike-grade `REQUIRED` fields go beyond canonical optionality.** Spike schema makes `parameter` REQUIRED on Part, `acceptance_criterion` REQUIRED on Requirement, `default_verification_method` REQUIRED on Requirement, `requirement.name` REQUIRED. Per [ADR/0005](../../Docs/ADR/0005-object-type-part.md) / [ADR/0006](../../Docs/ADR/0006-object-type-requirement.md), all these namespaces and the default verification method are OPTIONAL. Spike tightened them because the basic Wedge always has one of each; production must relax back to optional.
- **[MINOR] Single-file `event.schema.json` with `oneOf` payload** matches the [ADR/0023 §5](../../Docs/ADR/0023-wedge-spike-scope-and-runtime.md) layout sketch but per [Codex1 N5 (arc 20260530-1)](Codex1.md), [ADR/0003](../../Docs/ADR/0003-schema-governance.md) prefers per-event-type schemas for error legibility. Spike error messages from the `oneOf` validator are noisy ("does not match any of the subschemas"). Production should split into per-event-type schemas. Spike-acceptable per N5.

## 3. Proposed clarifications / corrections / Schema Change Notes

- **Schema Change Note candidate — extend `parameter_changed` event payload** with optional `new_fact_provenance` (carries forward the new provenance dict) OR define a normative fold rule that `parameter_changed` ⇒ `parameter.fact_provenance.category = "ai_proposal"`. The latter is cheaper (no schema change) but assumes AI Action Protocol is the ONLY transaction shape that produces `parameter_changed`. Worth Codex view on which to adopt at production-grade.
- **Schema Change Note candidate — canonical threshold-expression primitive on `acceptance_criterion`** OR formal commitment that thresholds are tooling-aided diagnostic (matching the [ADR/0021 §"Decision §7"](../../Docs/ADR/0021-relationship-types-v-and-v.md) verification-method-consistency posture). Either resolves the spike-local convention I had to invent; both are credible. Wedge-002 (V&V-instrumented) will exercise this further when TestExecution `produces` EvidenceArtifact actually evaluates a criterion.
- **Glossary clarification — workspace vs repo path convention** for Reservations + revisions + events.jsonl + Releases. Either standardize on `Docs/`-prefixed paths (AIADRA repo conventional) OR workspace-rooted paths (spike-local clean) OR explicitly two conventions for spike vs production.
- **Minor ADR amendment candidate — standardize `schema_version` placement per artifact kind.** Three different conventions across ADRs 0002 / 0004 / 0006 / 0009 makes each new artifact-kind ADR re-decide. A single short clarifying ADR or a sentence in [ADR/0002 Decision 4](../../Docs/ADR/0002-canonical-format.md) ("schema_version SHALL live at: object.schema_version for sidecars/Revisions; top-level for events/manifest; YAML-frontmatter for Reservations") would close it.
- **Wedge-002 scope hint surfaced by this spike:** the threshold-expression friction (#2 above) + the V&V framework's `verifies` / `tested_against` / `produces` chain mean that a V&V-instrumented Wedge-002 will need either the threshold-primitive Schema Change Note OR the tooling-aided posture pinned before it starts. Worth pre-resolving in the next arc's design.
- **No new ADR required from this friction log.** All items above are either Schema Change Notes (additive, scoped) or per-artifact-kind clarifications. The basic Wedge architecture — sidecars + events + Revisions + Manifest + cross-artifact invariant — survived contact with reality cleanly. The friction is in field-level details, not architectural shape. Per [OQ-0007](../../Docs/OpenQuestions.md): scope-adequacy advances toward `resolved` after Codex2 sign-off.

## 4. Codex2 round friction (added per [Codex2 N3 (arc 20260530-1)](../../Docs/Discussions/20260530/20260530-1/Codex2.md))

These items surfaced when Codex2 reviewed the round-1 artifacts. All three are now absorbed in the round-2 spike; the friction-as-spec-feedback is what's worth carrying forward.

- **[LOAD-BEARING → resolved in this spike — [ADR/0002 §1](../../Docs/ADR/0002-canonical-format.md) ambiguous-scalar quoting rule]** Round-1 spike emitted unquoted UUIDs / Numbers / versions / timestamps because `validate_yaml_profile()` only covered the structural Profile rules (anchors, aliases, merge keys, custom tags, YAML 1.1 directive, duplicate keys) and the dumper inherited ruamel.yaml's plain-string default. Spike-grade fix: (a) override `str` representer to force `style='"'` on every string scalar (over-quotes but always Profile conformant); (b) add raw-text regex scan for unquoted-ambiguous values in mapping-value and list-item positions; (c) extend negative-fixture suite from 6 to 11 covering unquoted UUID / Number / semver / timestamp / bool-like. **Friction for production:** the dumper over-quotes (`type: "Part"` rather than `type: Part`); cleaner production-grade is selective per-string-value quoting using `ruamel.yaml.scalarstring.DoubleQuotedScalarString` wrappers chosen by ambiguity check. Spike-grade lint also misses **two-segment version strings** (`"1.0"`) because the same regex matches the legitimate float `7.0` (false positive case); to lint these correctly without false positives, the lint needs to consult the schema field type (number vs string). Production-grade Profile linter should be token-stream-based, not regex-line-based — see [ADR/0002 Decision 1](../../Docs/ADR/0002-canonical-format.md) "token-level linter required in addition to JSON Schema".
- **[LOAD-BEARING → resolved in this spike — Windows newline conversion bug]** Round-1 spike's `atomic_write_text` called `Path.write_text()` which on Windows converts `\n` to `\r\n` in text mode by default. The hash computed from the in-memory text string therefore did NOT match the bytes on disk; the manifest pinned a hash that nobody could verify by reading the file. Spike-grade fix: `atomic_write_bytes()` writes raw UTF-8 bytes via `Path.write_bytes()`, no newline translation; `materialize_revision()` re-reads file bytes post-write and hashes those (single source of truth = disk); `cmd_release` runs `verify_revision_hashes()` after manifest write to re-verify the pin. **Friction for production:** Python's `Path.write_text` text-mode default is a silent footgun on Windows; production should standardize on byte-mode for all canonical artifact writes. Also surfaced: the manifest's own deterministic-JSON serializer (`json.dumps(..., sort_keys=True, separators=(",", ":"))`) already wrote raw bytes via `manifest_bytes.decode("utf-8")` then `atomic_write_text` — fine because JSON has no significant whitespace. Sidecars and Revisions were the affected artifacts.
- **[LOAD-BEARING → resolved in this spike — JSON Schema validation at every read]** Round-1 spike had `validate_against_schema()` but read paths used the bare `load_yaml()` and trusted the data shape afterwards. Per [ADR/0002 Decision 1](../../Docs/ADR/0002-canonical-format.md) and [ADR/0023 Decision 3](../../Docs/ADR/0023-wedge-spike-scope-and-runtime.md), the Profile requires schema validation **at every read**, not only at release-time check or write-time. Spike-grade fix: added `load_sidecar_validated()`, `load_revision_validated()`, `load_reservation_validated()`, `load_manifest_validated()`, `validate_event()` helpers in `validate.py` that walk the bundle-index `(artifact_kind, discriminator) → schema_path` lookup per [ADR/0003 §2](../../Docs/ADR/0003-schema-governance.md), then every spike read path (`_resolve_number_to_uuid`, `cmd_propose_parameter_change`, `add_relationship`, `change_parameter`, `materialize_revision`, `validate_fold`, `cmd_release`) was updated to call the validated helper instead of bare `load_yaml`. Events validated post-hoc via `validate_fold()` because no pre-parse path exists for streaming JSONL. **Friction for production:** the spike's load-validate pattern requires every read site to know the right helper; production-grade should likely make `load_yaml(path)` *itself* validate by reading the artifact's own `schema_version` + `artifact_kind` discriminators (self-describing artifacts that resolve their own schema via the bundle index). The `event_log.read_events` JSONL iterator does NOT pre-validate each event during streaming — validation happens later when `validate_fold` iterates the same stream. For at-rest event log integrity in production, a streaming validator wrapped around the JSONL reader would be preferred.
- **[MINOR → resolved in this spike] Reservation schemas now forbid retired-only fields when `status: current`.** Per [ADR/0004 §3](../../Docs/ADR/0004-number-allocation.md) ("`retired_at` REQUIRED when `status: retired`; FORBIDDEN when `status: current`"). Per [Codex2 N2 (arc 20260530-1)](../../Docs/Discussions/20260530/20260530-1/Codex2.md): both `reservation_P.schema.json` and `reservation_REQ.schema.json` extended with an `if status: current then not anyOf [{required: retired_at}, ...]` clause. Spike does not exercise retirement (no `number_rebound` Transaction) but the schema is now ADR-faithful.

## 5. Codex3 round friction (added per [Codex3 B1 + N5 (arc 20260530-1)](../../Docs/Discussions/20260530/20260530-1/Codex3.md))

- **[LOAD-BEARING → resolved in this spike — read-time validation completeness]** Round-2 spike validated sidecars/Revisions/Reservations/manifest at every read, BUT event-log sequencing (`next_event_id`, `next_transaction_id`, `last_event_id_and_hash`, `fold_state`) still consumed the raw JSONL iterator and trusted whatever JSON parsed. Per Codex3 B1: a malformed-but-parseable event record could still influence sequencing values used by a subsequent write to Reservation/sidecar/event before the post-write `validate_fold` caught it. Spike-grade fix: `event_log.read_events()` is now the validated iterator (lazy-imports `validate.validate_event` to avoid circular import); `_read_events_raw()` is internal-only. `last_event_id_and_hash` validates each event during the line-scan since it needs raw bytes for hashing. All sequencing helpers + fold derivation now go through validated reads. **Friction for production:** the lazy-import pattern works but is a code-smell; production-grade should refactor event validation into a standalone module that both `event_log` and `validate` import from, OR adopt a streaming-validated JSONL reader from day one.
- **[MINOR → resolved in this spike] Single-bang `!localtag` custom tags were not lint-rejected** because the regex caught only `!!...`. Per [Codex3 N5 (arc 20260530-1)](../../Docs/Discussions/20260530/20260530-1/Codex3.md): ADR/0002's examples focus on `!!...` but "custom tags" reads broadly. Spike regex extended to `!{1,2}[A-Za-z]` (single or double bang); new fixture `single_bang_tag.yaml` proves rejection. Error message updated to "YAML custom tags (! or !!)" for accuracy. Negative-fixture suite grew 11→12.
