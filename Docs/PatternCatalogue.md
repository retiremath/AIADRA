# Active Pattern Catalogue

> Stable reference table of the active schema/serialization/binding patterns. Split out of [SystemState.md](SystemState.md) §2 in arc 20260602-3 (SystemState is the session cache; this catalogue is durable reference material). SystemState §2 points here.

| Pattern | Declared by | Applies to | Watch-out |
|---|---|---|---|
| Source-anchored asymmetric binary serialization (implicit source + single serialized target) | [ADR/0009 §1](ADR/0009-relationship-type-satisfies.md), [ADR/0010 §1](ADR/0010-relationship-type-composed-of.md) | `satisfies`, `composed_of`, `derived_from`, `refines`, `allocates_to`, `depicts` | Legitimate break for symmetric / multi-endpoint relationships per [ADR/0011 §1](ADR/0011-relationship-type-mated-to.md); `depicts` extends this pattern with an `occurrence_context` sub-field on the target endpoint when documenting placed instances (necessitated by the Drawing source-anchor's lack of implicit Assembly visibility) |
| Undirected multi-endpoint serialization (all semantic endpoints serialized; owning Object is storage carrier) | [ADR/0011 §1](ADR/0011-relationship-type-mated-to.md) | `mated_to`; future undirected geometric | Owning Object is carrier, not semantic endpoint |
| Asymmetric multi-endpoint serialization (separate `output_endpoint` singleton + `input_endpoints` list with stable ids; first **fact-level endpoint addressing** — parameter addresses `<object_uuid>:parameter:<id>`; expression payload with explicit `variables[]` symbol-to-endpoint bijection) | [ADR/0015](ADR/0015-relationship-type-parameter-expression.md) | `parameter_expression` | Output endpoint MUST NOT carry `occurrence_ref` (no occurrence-local outputs in seed); `variables[]` bijection enforces canonical dependency set; cross-Object scope of `acyclic_dependency` closure |
| Direct-binding (relationship-level Float / Fixed; default Float; release materializes Fixed) | [ADR/0009 §4](ADR/0009-relationship-type-satisfies.md), [ADR/0010 §5](ADR/0010-relationship-type-composed-of.md) | `satisfies`, `composed_of`, `derived_from`, `refines`, `allocates_to`, `depicts` | Legitimate break for indirect-binding relationships per [ADR/0011 §5](ADR/0011-relationship-type-mated-to.md) |
| Indirect-binding (no relationship-level binding; delegated to address mechanism; endpoint `revision_id` as cross-check) | [ADR/0011 §5](ADR/0011-relationship-type-mated-to.md) | `mated_to`, `parameter_expression` | Endpoint `revision_id` is never authority; hard-fail on mismatch with occurrence-path resolution |
| Multi-endpoint stable ids (endpoints with n≥2 carry stable local id per S0 commitment 7) | [ADR/0011 §3](ADR/0011-relationship-type-mated-to.md) | `mated_to`; future multi-endpoint | Single-endpoint relationships don't need ids (positional addressing OK) |
| Engineering-structure direct-external-endpoint NO default | [ADR/0008 §4](ADR/0008-cross-project-object-identity.md) | `composed_of`, `mated_to`, `parameter_expression`; future structural | Catalog reuse routes through local Binding Objects |
| Trace-relationship direct-external-endpoint opt-in (with Float external semantics) | [ADR/0009 §3](ADR/0009-relationship-type-satisfies.md) | `satisfies`, `derived_from`, `refines`; future trace relationships likely | Float external resolves to current released Revision; never working sidecar |
| Requirement-to-Requirement trace relationships (`trace_graph` cycle class; partial supersession of [ADR/0006 §"Decision 12"](ADR/0006-object-type-requirement.md) `acyclic_dependency`) | [ADR/0012](ADR/0012-relationship-types-derived-from-and-refines.md) | `derived_from`, `refines` | Cycles are graph-class-valid but semantically suspicious; tooling may warn, schema does not hard-fail |
| External pointer Object pattern operationalized (local Binding Object with discriminator-specific upstream binding; release-time content-hash integrity; mirrored `published_ref` with `upstream_fact_ref` chain validation; algorithm-qualified hash convention pinned by ADR/0016) | [ADR/0014](ADR/0014-object-type-component.md), [ADR/0016](ADR/0016-object-type-software-module.md) | Component, SoftwareModule (future MaterialSpec-like, etc.) | Local Binding Object owns adoption lifecycle. AIADRA Core hosts no registry / resolution service per [Manifesto P11](Manifesto.md). Released mates targeting Component-owned published_refs hard-fail if the upstream chain (pinned Revision → upstream pr id) doesn't resolve. SoftwareModule additionally invokes a *direct Promotion path* (basic capability test) for `workspace_git` first-party modules; the Binding-lifecycle path applies only when the discriminator is one of the four external-source values. |
| Attachment-bearing Object pattern operationalized (canonical bytes attached via new `attachment:` namespace; D7-escape made structural through required `source_authoring` role at release; derived roles carry `derived_from_attachment_id` lineage terminating at source; algorithm-qualified `content_hash` is authority, `vault_path` is non-authoritative locator hint; per-Type specialization of `source_authoring` semantic is the established template pattern) | [ADR/0017](ADR/0017-object-type-drawing.md), [ADR/0019](ADR/0019-object-type-evidence-artifact.md), [ADR/0020](ADR/0020-object-type-test-procedure.md) | Drawing, EvidenceArtifact, TestProcedure, TestExecution (future annotated-simulation candidates, etc.) | Every released Attachment-bearing Object MUST carry at least one `source_authoring` attachment with resolved `content_hash`. Derived attachments (rendered_primary / derived_secondary) MUST point back via `derived_from_attachment_id`; lineage chain terminates at `source_authoring`; cycles / dangling references hard-fail. Hash-against-retrieved-bytes mismatch is hard-fail at fetch / release. **Per-Type specialization of `source_authoring` semantic:** Drawing = authored canonical drawing payload; EvidenceArtifact = canonical evidence payload (raw result / signed report / measurement log; setup-only forbidden) AND every `parameter:` record carries `fact_provenance.derived_from` lineage to supporting `attachment:` records (full chain: parameter → derived_from → attachment → content_hash → Vault bytes); TestProcedure = canonical procedure document (signed test plan / SOP / test script / runbook / regulatory protocol; metadata-only stub forbidden) — TestProcedure `parameter:` records are nominal design facts, no `derived_from` lineage discipline; TestExecution = canonical record of the execution event (raw instrument output / signed inspector report / automated test framework output / video log; metadata-only stub forbidden) AND every `parameter:` record carries `fact_provenance.derived_from` lineage to supporting `attachment:` records (parallel to EvidenceArtifact — TestExecution parameters are observed measurements, not nominal design facts). AIADRA Core hosts no Vault, no renderer, no central registry per [Manifesto P11](Manifesto.md). |
| Deliverable-vs-emergent governing principle for `allocates_to` target inclusion (with wrong-verb authoring guardrail discipline within "MAY") | [ADR/0017 §"Decision §5"](ADR/0017-object-type-drawing.md), [ADR/0019 §"Alternatives §C"](ADR/0019-object-type-evidence-artifact.md), [ADR/0020 §"Decision §5"](ADR/0020-object-type-test-procedure.md) | `allocates_to` target Type union: `Part \| Assembly \| Component \| SoftwareModule \| Drawing \| TestProcedure` (EvidenceArtifact excluded) | Committed-to-produce deliverables MAY be `allocates_to` targets (Part / Assembly / Component / SoftwareModule / Drawing / TestProcedure). Emergent records MAY NOT (EvidenceArtifact — emerges from execution; right verb is `cites` per [ADR/0021](ADR/0021-relationship-types-v-and-v.md)). Within "MAY," per-Type wrong-verb authoring guardrails further constrain *which* Requirements can target the deliverable. TestProcedure-specific: only procedure-deliverable Requirements ("project shall publish a documented procedure") may target a TestProcedure; product Requirements awaiting verification ("bracket shall withstand 5400 N") target the `verifies` edge per [ADR/0021 §2](ADR/0021-relationship-types-v-and-v.md) instead. Schema cannot semantically distinguish; tooling MAY surface as non-blocking diagnostic. |
| Criterion-level Requirement addressing (optional `endpoints[].fact_ref` on target Requirement endpoint; optional `source_fact_ref` at relationship-record level for Requirement-source relationships; resolves against Requirement's `acceptance_criterion:` namespace; whole-Requirement remains the default; **per-relationship-schema opt-in discipline** — each relationship-type schema explicitly permits or rejects each primitive) | [ADR/0021 §"Decision §6"](ADR/0021-relationship-types-v-and-v.md) | `verifies` (target-side opt-in), `cites` (source-side opt-in); `tested_against` and `satisfies` do NOT opt in in this bundle (reserved for future opt-ins via Schema Change Notes — `satisfies` retrofit explicitly deferred per ADR/0021 §6) | Schema-rejects dangling `acceptance_criterion:<id>` references against the resolved Requirement Revision's `acceptance_criterion:` namespace. Whole-Requirement and criterion-scoped claims for the same Requirement-Pair coexist; tooling MAY surface as redundant but neither schema-rejected. Reopens [ADR/0009 §"Alternatives §E"](ADR/0009-relationship-type-satisfies.md) deferral under the condition ADR/0009 named (V&V taxonomy now exists). The primitive being defined at the trace-relationship base schema level does NOT retrofit `satisfies` — explicit per-relationship-schema opt-in required. |
| Cross-project per-type asymmetry across the trace-relationship family (target-Type-governs precedent operationalized per-type with explicit rationale dimensions) | [ADR/0009 §3](ADR/0009-relationship-type-satisfies.md), [ADR/0013 §"Cross-project"](ADR/0013-relationship-type-allocates-to.md), [ADR/0018 §"Decision"](ADR/0018-relationship-type-depicts.md), [ADR/0021 §§2-4](ADR/0021-relationship-types-v-and-v.md), [ADR/0022 §7](ADR/0022-test-execution-model.md) | `satisfies` IN, `derived_from` / `refines` IN, `allocates_to` OUT, `depicts` OUT, `verifies` IN, `tested_against` OUT, `cites` IN (with explicit EvidenceArtifact-specific rationale), `executes` OUT, `executed_on` OUT, `produces` OUT (all three with explicit event-locality rationale per ADR/0022) | Per-type rationale dimensions are: local-approval semantics, Binding-Object-applicability, integrity anchoring, Float-vs-Fixed meaningfulness; ADR/0022 adds a fifth dimension for execution-instance relationships — **event-locality** (execution events are intrinsically local; cross-project authoring of a run that happened in another project's lab is structurally meaningless). Deliverable-vs-emergent governing principle informs but does not directly determine cross-project posture. Shape-only inference is rejected (per ADR/0013 / ADR/0021 Blocker 3 — explicit per-type case required when target Type differs in any of the four dimensions). EvidenceArtifact-specific (ADR/0021 §4): consumer's `cites` is the local approval act; no Binding Object needed; Revision content hash implicitly pins attachment-hash-chain integrity per S2 immutability; Float "current best evidence" semantic meaningful + Fixed for historical pinning. |
| Execution-instance relationship category (Fixed-only binding posture + unconditional Revision pinning + cross-project opt-OUT default + per-relationship-type cardinality-at-release with status-sensitive refinement) | [ADR/0022 §3-§8](ADR/0022-test-execution-model.md) | `executes`, `executed_on`, `produces` (future observation / measurement / event-recording relationships) | (a) **Fixed-only binding** (Float schema-rejected — execution records are historically anchored; "this past run tracks current Revision" is semantic nonsense); (b) **`endpoints[0].revision_id` REQUIRED** unconditionally (not Conditional); (c) **cross-project endpoints opt OUT** default (event-locality dimension reinforces target-Type-governs); (d) **per-relationship-type cardinality-at-release rules with status-sensitive refinement** (`executes` exactly 1 hard-fail; `executed_on` ≥1 hard-fail; `produces` ≥0 globally with `completed` SHOULD ≥1 diagnostic, `aborted` MAY 0, `inconclusive` MAY 0 or ≥1 — first introduction of status-sensitive cardinality); (e) **no `endpoints[].fact_ref` / `source_fact_ref`** (no Requirement endpoint — per-relationship-schema opt-in discipline from ADR/0021 §6 explicitly does not apply). Together these properties distinguish execution-instance relationships from design-intent trace relationships; future categories (observation / measurement / event-recording) inherit this posture wholesale. |
| **Ecosystem packages shrink as core grows** (a Native Engine consumes the production `aiadra-core` API rather than reimplementing spike-grade equivalents) | arc 20260602-1 [FINDINGS §9](../aiadra-mechanical/FINDINGS.md) (Wedge-003 ~1,500 LOC → `aiadra-mechanical` v0.0.1 ~600 LOC) | future Native Engines + Data Adapters | Novel surface concentrates in the kernel-integration + cache layers; the AIADRA-loop plumbing (sidecar / event / provenance / release) is all inherited. Do NOT re-vendor what core provides. |
