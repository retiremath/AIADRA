# ADR/0036 — View-dependent HLR: the Display Representation contract v1.1

## Frontmatter

- **Status:** Accepted — 2026-06-10 (arc 20260609-2; three-round convergence Claude1 + Codex1 / Claude2 + Codex2 / Claude3 close absorbing Codex2 B1+B2 verbatim). The HLR spike — [ADR/0033](0033-studio-display-ux-vision.md) D10 **step 4**, the direct continuation of the [ADR/0035](0035-display-representation-contract-and-topology-identity.md) foundation (which reserved the slot this ADR fills).
- **What it is:** pins the **view-dependent HLR payload** that populates the contract's reserved `view_dependent` slot (→ **contract v1.1**, additive), the **`display_hlr` read primitive** (the per-camera-settle counterpart to `display_representation`), the **contract-complete 2D view frame**, the **correlation + disambiguation policy** that keeps HLR output anchored to the foundation's stable identity, and the **ephemeral-identity firewall** for silhouettes. Proven on the box-with-hole across two fixed views + a tilt view that splits an edge into visible+hidden segments.
- **Realizes:** ADR/0033 D6 (OCCT HLR, view-dependent, cached on settle, exact+poly, never per-frame), D10 step 4. Unblocks D7 (the Hidden Line / No Hidden display modes + curved-surface silhouettes — step 5 consumes this payload).
- **Version impact:** Display Representation contract **1.0 → 1.1** (additive — a v1.0 package with a null slot stays valid; a v1.0 package with a populated slot stays rejected). `aiadra-core` **0.12.0 → 0.13.0** (additive public Tier-1 surface: `display_hlr()` + the view-dependent contract types). `aiadra-mechanical` code-only (`adapter_schema_version` stays 0.1.1 — no authoring-payload change). **No bundle / schema / Glossary / Manifesto / TruthModelSchema change** — view-dependent display data is not Product Truth.

## §0 — What this ADR does

The foundation deliberately deferred everything view-dependent: visible/hidden classification and curved-surface silhouettes — the two things the screen-space stopgap could never produce and the reason it was end-of-lifed. This ADR pins how that payload is computed (OCCT `HLRBRep`, engine-side), what shape it ships in (the v1.1 `ViewDependentPayload`), how its output stays anchored to the foundation's stable topology identity (correlation against the SAME records, never a parallel derivation), and how it reaches the renderer (a separate read primitive sized to the camera-settle cadence). A pre-build probe (arc 20260609-2 S7) verified the OCP bindings, the coordinate frame, the absence of provenance APIs, sliver behavior, and timings — and surfaced the coincident-projection trap that D5's disambiguation policy answers.

## Decisions

### D1. The `view_dependent` payload — `ViewDependentPayload` (contract v1.1, additive)
The slot holds `{identity_echo, views[]}`. Each `HlrView`: `view_id` / `projector` (D2) / `algorithm` (`"exact"` | `"poly"`) / `coordinate_space` (`"view_plane_2d"` — the only v1.1 value; a future 3D discriminator is additive) / `correlation_min_length_mm` (D6) / classified `segments[]` / `counters` (visible / hidden / outline / **discarded_tolerance_segments** / generation_ms). Each `HlrSegment`: a flat 2D `polyline_2d`, `visibility` (`visible`|`hidden`), `edge_class` (`sharp`|`smooth`|`sewn`|`outline` — OCCT's HLR vocabulary, a DIFFERENT axis from the model-edge `kind` enum), and a **strict source union** (D4). Partial visibility falls out naturally: one model edge appears as N segments with mixed visibility, all carrying the same `edge_id`. Counters are validator-checked against the segments — the acceptance baseline must be trustworthy. Core accepts producer versions `"1.0"` and `"1.1"`; the v1.0 populated-slot rejection survives verbatim (Codex1 Q7).

### D2. The view frame is contract-complete and producer-independent (Codex1 B2)
`projector` = `{projection: "orthographic", origin, direction, up, right, units: "mm"}` — all unit vectors, validator-enforced: `direction` is the LOOK direction (eye → scene; camera convention); `right = normalize(direction × up_request)`; `up` is the echoed ORTHONORMALIZED true up (`right × direction`); `(right, up, -direction)` right-handed; mapping `u = (p − origin)·right`, `v = (p − origin)·up` in mm. The core validator re-derives `right` and rejects any deviation — the basis is contract-pinned, not producer-specific. **Probe-grounded:** OCCT's HLR output lives in the projector plane (all z == 0), gp_Ax2's auto-derived basis is NOT a drafting frame, and the projector's main axis points scene → eye — so the engine constructs `gp_Ax2(origin, −direction, Vx=right)` explicitly. Perspective is a reserved enum value, not half-defined.

### D3. A separate `display_hlr` read primitive — per-settle economics (Codex1 Q2)
`display_hlr(workspace, object_ref, *, views, algorithm="exact", tolerance=None, correlation_min_length_mm=None) → ViewDependentPayload` on the ADR/0035 D4 read lane (registered engine read op `mechanical.display_hlr`; non-staging context; no draft, no audit). Camera settle is the high-frequency event and topology change the rare one — the overlay ships alone, never the render buffers. **`identity_echo` carries SIX fields** (Codex1 B3): `object_uuid`, `object_number`, `geometry_ref`, `display_representation_version`, `cache_key`, `topology_signature`. Studio attaches an overlay only when ALL match the held package (`attachHlr.ts`); the core validator enforces the same six-field agreement for INLINE payloads against the enclosing package identity — including the contract version (Codex2 B2). Inline population remains legal (a future self-contained drawing/export package); the interactive path never uses it.

### D4. The ephemeral-identity firewall for silhouettes (Codex1 B5)
Outline (silhouette) segments carry `source = {kind: "outline", face_id, index}` — anchored to the (stable) generating face, with a deterministic per-view ordinal. They are NEVER display ids: no `edge_id`, never pickable, never in `selection.names`; `model_edge` sources conversely never carry `face_id`/`index`. The union is validator-enforced in both directions, per edge_class. Model-edge segments carry the canonical `edge_id` from the shared topology records (D5) — stable, selection-grade, survives parameter edits (the across-edit invariant extends to HLR: same view after a depth edit yields the same correlated id set with a stable `topology_signature`).

### D5. One topology identity source — the shared extraction layer (Codex1 B1, the hard stop)
`aiadra-mechanical/topology.py` owns ALL identity derivation: face roles, edge ids/kinds, model-space sampled curves, `topology_signature`, plus the live OCCT handles correlation needs (engine-internal only — handles are never serialized). `display.build_display_payload()` and `hlr.generate_hlr()` consume the same `PartTopology`; HLR **inherits** the recipe-first/geometry-second invariant instead of cloning it (test-enforced: base display ids == records ⊇ HLR model-edge ids, exact and poly, end-to-end). Correlation is geometric (no OCCT provenance API exists — probe P4): model edges are projected with the same frame and matched by sampling. **The pinned disambiguation policy** (probe-surfaced: a rim circle seen edge-on projects colinear with box edges): (1) single candidate within tolerance → take it; (2) **extent affinity** (projected-bbox-diagonal match — robust for closed curves where endpoint matching degenerates); (3) **uniquely most-specific candidate** (fragments: the smallest-extent containing candidate, when uniquely minimal); (4) **depth rule** (visible → nearest the eye, hidden → farthest); (5) fail loud. **Named limitation:** in poly mode a fragment among colinear candidates can evade (3) and fall to (4), which may misattribute between colinear peers — positionally invisible (the polyline is what renders), factually imperfect; exact is the settled-quality lane (ADR/0033 D6), and hardening would need depth data the bindings don't expose. Accepted for the spike (Codex2 acceptance note).

### D6. The sliver policy — counted, never silent (Codex1 B4)
An UNCORRELATABLE non-outline segment shorter than `correlation_min_length_mm` (default **0.01 mm**; probe: exact slivers = 0, poly fragments ≥ 0.145 mm) is dropped and counted in `counters.discarded_tolerance_segments`; at or above the threshold it raises (`TransactionError`) — a material uncorrelatable segment is a correlation bug, not rendering guesswork. Correlatable slivers are kept. The threshold rides in each view payload and in the cache key.

### D7. HLR caching — keyed on FULL identity + view material (Codex2 B1)
Per-process engine cache (ADR/0028 D6 advisory posture): key = the six B3 identity fields **plus** view frames, algorithm, threshold, and tolerances. The D8 `cache_key` alone is geometry/freshness material — two distinct objects sharing a recipe share it, and since the cached value embeds `identity_echo`, geometry-only keying would return the first object's echo for the second (which Studio's attach check would then correctly refuse — a valid request yielding an unusable overlay). Regression-tested with two objects sharing recipe + cache material. HLR is computed on camera-settle and NEVER per-frame; orbit interaction renders the static package (ADR/0033 D6 verbatim).

### D8. Scope boundary + measured baselines
**In:** the v1.1 payload + validation matrix, `display_hlr` end-to-end (engine → core → bridge → IPC → TS types + attach check), exact + poly, the spike proofs (front view: the hole's silhouette as hidden outline segments; tilt view: a genuine visible+hidden split of one `edge_id` — a box is convex, only the hole concavity splits edges; across-edit invariant; determinism; cache). **Out:** the display-mode taxonomy/UI + line styling (step 5); appearance/nav-cube/selection-interaction UI (step 6); perspective projection; drawing/print export; HLR for reference imports. **Measured (box-with-hole):** exact HLR 0.9–61 ms, poly ≤ 3.7 ms (budgets: exact < 150 ms, settle-to-overlay < 300 ms, orbit 60 fps untouched); suites at close: aiadra-mechanical 63, aiadra-core 406, aiadra-studio 49 vitest + tsc + build.

## Consequences
- The renderer can now draw **true hidden-line views**: classified visible/hidden segments for model edges (correlated to stable ids) + curved-surface silhouettes — the Creo-benchmark items (display modes, step 5) build directly on this payload.
- The read lane gains its second primitive; the pattern (separate overlay reads at interaction cadence, identity-echoed, attach-checked) is reusable for future view-dependent products (drawings, print).
- The contract's versioning discipline is exercised for real: v1.1 landed additively, producers upgrade independently, and the validator enforces every promise made when the slot was reserved.

## Alternatives rejected
- **A `views=` parameter on `display_representation`** — would re-ship faces/edges/vertices on every camera settle, inverting the cache design (D3).
- **3D model-space HLR polylines** — OCCT computes in the projection plane; inventing depth the kernel didn't output violates the no-guesswork posture. The `coordinate_space` discriminator keeps a future 3D lane additive (D1/D2).
- **Endpoint-affinity disambiguation** — degenerates on closed curves (a circle's discretization starts and ends at one point); replaced by extent affinity (D5).
- **Geometry-only HLR cache keying** — cross-contaminates `identity_echo` between recipe-identical objects (Codex2 B1; D7).
- **Outlines with no identity at all** — worse tests and debugging without strengthening the firewall; the strict union already makes confusion structural (Codex1 B5; D4).
- **Per-view identity echoes** — all views in one response share one evaluated package state; per-view repetition is churn without safety (payload-level echo, Codex2 acceptance).
